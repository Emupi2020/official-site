# 歌まねリクエストの画面ルール

リスナー画面、管理画面、配信用ルーレットに適用する。数値は CSS px。既存画面と異なる箇所で迷ったら、下の「同じ役割には同じ見せ方」を基準に揃える。

## 同じ役割には同じ見せ方

| 要素 | 使う条件と理由 |
| --- | --- |
| ブロック・囲い | 確認ダイアログや管理表など、ひとまとまりとして操作する範囲に使う。リスナーの通常フォームは入力欄自体に枠があるので、周囲は白地に置く。 |
| 横線 | 同じ一覧の隣り合う行を見分けるために使う。ジャケット付きの選択行では文字の左端から引く。全画面メニューの項目は行間で区別する。 |
| 選択行の押下 | リクエスト・次回の予約・右上の両メニュー・歌える曲の一覧で、行を押したときは薄いグレーを画面の左右端まで表示する。文字・画像・区切り線の位置はそのまま。指を離したら短く消え、スクロールでの取り消しやページを戻るときも色を残さない。キーボードのフォーカス表示は維持する。 |
| 色 | 青は押して実行できる操作、薄いグレーは補足、赤はエラーや注意。曲の状態だけは専用タグの色を使い、状態名も併記する。 |
| 太字 | ページ見出し、曲名、枠名など見つける対象に使う。歌手名、日付、補足文は通常の太さ。 |
| 縦並び | 読む順や操作の順がある場合に使う。曲名の下に歌手名、保存の下にキャンセル。 |
| 横並び | 同じ曲の情報や、同列の選択肢に使う。日付は歌手名と同じ行に収まるときだけ右寄せ。幅が足りなければ日付の単位で折り返す。 |
| 左右の役割 | 左は画像・曲名・項目名、右は日付・件数・状態・遷移の矢印。文字は左揃え。独立した通知や全幅ボタンのラベルは中央揃え。 |
| 操作部品 | 送信・変更・確定はボタン、他サイトへの遷移はリンク、一覧や詳細への遷移は行全体を押せるようにする。入力中のキャンセルは操作終了として残し、ページの戻る操作にはブラウザ履歴を使う。 |

## リスナー画面の共通値

| 用途 | 値 |
| --- | --- |
| ページ背景 | 白 `#fff`。ログイン前後で共通 |
| テキスト | 主文 `#1d1d1f`、補足 `#686870`、操作 `#0071e3`、警告 `#a82e25` |
| ヘッダー | 高さ44＋端末の上側セーフエリア。背景 `rgba(251, 251, 253, .8)`、下に1pxの境界線 |
| メニュー背景 | `#fafafc`。ヘッダーの上から全画面に展開 |
| 本文 | 最大幅480、左右16。システムフォントを優先 |
| 小さな文字 | ヘッダーのサービス名11、挨拶15・ウェイト400、フッター12、注意事項の入口13 |
| 選択行 | 高さ80以上。左の画像ボックス76角、文字との間7。右矢印 `#c7c7cc`、サイズ7、線幅2 |
| 履歴・候補の曲情報 | コンパクトな画像42角、曲名16・ウェイト650、歌手名13、日付12。日付は `YYYY/M/D`、時刻は省く |
| フッター | 上に境界線、上下16。トップに限りコピーライトの下に「注意事項」を表示し、矢印なしで展開 |

### 曲の画像と状態

- 山P枠は白いジャケット `yamapi-white.png`。「それ以外の歌まね」は赤い筆のバツ入り `other-smoke.png`。トップ・次回予約・ユーザーメニュー・曲詳細・履歴等で同じ枠の画像を使う。写真に置き換えず、角は大きい画像で5、コンパクトな画像で3を基準に丸める。
- 曲情報があるときは「曲名 → 歌手名」。枠を選ぶトップでは「山Pの歌まね」「それ以外の歌まね」が行の主見出しで、登録曲があれば下に曲名を添える。
- 状態は曲の情報と同じ行の右側を基本とする。履歴の日付と状態は別の情報として扱う。「曲を変更」は曲詳細の下に置き、抽選前の変更可能な状態で表示する。
- タグは11、ウェイト600、上下3・左右7、丸型。最大12文字分の幅を目安に必要なら折り返す。選択行の矢印はタグの色に連動させない。

| 状態 | 背景 | 文字 |
| --- | --- | --- |
| 未リクエスト・見送り | `#f0f0f3` | `#515158` |
| リクエスト済み・抽選待ち | `#e9f2ff` | `#174c83` |
| 予約済み | `#f0eafb` | `#62428d` |
| 当選・当選済み | `#e4f4eb` | `#206744` |
| 一時保留・次回に持ち越し | `#fff0d5` | `#774613` |
| 取り下げ済み | `#fbe8e7` | `#8d3235` |

## リスナー画面ごとのルール

- **入口**。「はじめての方」「ログイン」は画面下部に縦並び。初回はパスコード設定、ログインは名前とパスコードを標準表示。名前だけの選択肢は下部リンク。同列のリンクが2件あるときだけ縦線で区切る。名前だけで始める場合の注意は赤。ログアウト結果は入口のボタンのすぐ上に短時間表示する。
- **トップ**。ヘッダー左のPはリクエストトップに戻る。その隣に「歌まねリクエスト β版」を細い文字で置く。本文は小さな挨拶の下に山P、それ以外の順で2行。枠ごとに1曲。募集回の番号はリスナーに表示しない。
- **募集・次回予約**。受付・順番待ち・予約は同じ曲詳細と入力パターンを使う。「次回の抽選をお待ちください。」は中央、18・ウェイト600。予約できる場合だけ説明と「次回の予約」をその下に置く。予約済みなら待機メッセージまで。
- **フォーム**。「歌手名」「曲名」などは入力枠内で空欄時15、入力済み・フォーカス時・プルダウンは左上の11。入力欄は全幅、高さ52、枠1px `#7d7d7f`、角10、背景 `#fdfdfd`。フォーカスは青。曲・名前変更フォームの行間は8、最後の入力欄から操作列まで16。入力文字16。山P枠の歌手名はプルダウン、それ以外は自由入力。曲候補は歌手と紐づけ、ひらがなの読みは入力補助として扱う。
- **フォームの操作**。「リクエスト」「予約する」「変更する」など目的が分かる文言を使う。曲の編集は「曲を変更」。変更フォームの主操作は全幅、高さ48以上、角10。キャンセルは直下に中央配置した下線付きの文字で、押せる高さは44以上。必須入力が揃うまで送信ボタンは無効。重複で送れなかったときの赤い説明は、その操作への応答として表示する。
- **三本メニュー**。上から「今回の募集で歌い終った曲」「歌える曲」「公式ホームページ」「バグ報告/ご意見」。最後に16px空けて「トップ」を置く。項目は高さ52以上、14・ウェイト600。項目間は余白で区別する。
- **ユーザーメニュー**。「リクエスト中の曲」を22で表示し、抽選待ちの自分の曲を最大2件。「リクエストを確認」はその下に全幅・高さ48以上・角10。その次に薄い「プロフィール」（14）を置き、項目に17角の線アイコンを添える。「ログアウト」は最下段で、実行前に確認する。
- **メニュー共通**。人物アイコンは三本線の左。閉じる×は両方で三本線と同じ位置。展開は400msで、項目は50msずつずらす。端末の動きを減らす設定を尊重する。
- **歌える曲の検索**。各階層のタイトルと曲数の下に検索欄を置く。トップでは全曲、カテゴリや歌手の画面では開いている範囲を曲名・歌手名で絞り込む。結果は曲数と曲一覧を表示する。
- **一覧の範囲**。「リクエスト履歴」は自分の記録。「今回の募集で歌い終った曲」は現在の募集分。「歌える曲」は歌唱記録から作り、山Pとそれ以外に分ける。履歴と歌唱済みは記録の日付を付ける。結果一覧とリクエスト画面は開いたときに取得し、送信・変更後はその操作の結果を取り直す。

## 管理画面と配信用ルーレット

- **管理の並び**。「今回当選中の曲」とその操作、その下に「ルーレット表示」。線で区切った下に「募集済みリスト」。山Pとそれ以外、抽選前と処理後を分け、各表は初期状態で閉じる。管理本文は最大1060、左右24。幅600以下では左右16。
- **行の操作**。三点メニューから、その状態で意味のある操作だけを出す。抽選前は曲の変更や取り下げなど、処理後は抽選待ちへ戻す、歌えない理由の訂正など。個別の初期化はそのユーザーのその曲に作用する。右上の三本メニューに「バグ報告」「管理」。
- **ルーレット**。管理の表から全画面で開く。「両方」「山P」「それ以外」の切り替えは幅312まで、各ボタンは高さ40以上。初期選択は山P。中央の青いP（直径60〜84）が回す操作。下の「設定」で回転時間を調整し、プレビューする。
- **結果**。回転中の盤面は曲名、停止後は中央の結果オーバーレイに曲名（30〜64）、下に歌手名（18〜28）。配信画面の結果に応募者名は載せない。「歌えない」「次回歌う」は当選結果に対する操作。「歌えない」の理由は「知らない」「音源なし」。抽選結果を訂正したときは公開側の結果にも反映する。
- **更新と日付の境界**。管理は表示中に10秒ごとに取り直す。「次回配信を開始」の手動操作に加え、日本時間15時の切り替えがある。リスナーの「今回」の歌唱一覧は募集回単位で、配信日が切り替わっても募集が続く間は同じ一覧を使う。

## 実装を確認する場所

- リスナーの構造と文言は [index.html](index.html) と [listener.mjs](listener.mjs)。
- 色・曲の行・入力・状態タグは [style.css](style.css)。ヘッダーとフッターの共通寸法は [site-frame.css](site-frame.css)、リスナー固有の指定とメニューは [site-menu.css](site-menu.css)。
- 管理・抽選の構造と操作は [admin.html](admin.html) と [admin.mjs](admin.mjs)、配信用の寸法は [roulette-tabs.css](roulette-tabs.css)。
- 変更時は同じ役割の画面を横断して確認する。とくにスマホ幅、長い歌手名、未入力・入力中・入力済み、抽選前後、両方のメニュー、ブラウザの戻る操作を確認する。
