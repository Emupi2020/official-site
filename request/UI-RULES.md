# 歌まねリクエストの画面ルール

リスナー画面、管理画面、配信用ルーレットに適用する。数値は CSS px。既存画面と異なる箇所で迷ったら、下の「同じ役割には同じ見せ方」を基準に揃える。

用語は [GLOSSARY.md](../GLOSSARY.md) に従う。

## 同じ役割には同じ見せ方

| 要素 | 使う条件と理由 |
| --- | --- |
| ブロック・囲い | 確認ダイアログや管理表など、ひとまとまりとして操作する範囲に使う。リスナーの通常フォームは入力欄自体に枠があるので、周囲は白地に置く。 |
| 横線 | 同じ一覧の隣り合う行を見分けるために使う。ジャケット付きの選択行では文字の左端から引く。全画面メニューの項目は行間で区別する。 |
| 選択行の押下 | リクエスト・次の抽選枠への予約・右上の両メニュー・歌える曲の一覧で、行を押したときは薄いグレーを画面の左右端まで表示する。文字・画像・区切り線の位置はそのまま。指を離したら短く消え、スクロールでの取り消しやページを戻るときも色を残さない。キーボードのフォーカス表示は維持する。 |
| 色 | 青は押して実行できる操作、薄いグレーは補足、赤はエラーや注意。曲の状態だけは専用タグの色を使い、状態名も併記する。 |
| 太字 | ページ見出し、曲名、枠名など見つける対象に使う。アーティスト名、日付、補足文は通常の太さ。 |
| 縦並び | 読む順や操作の順がある場合に使う。曲名の下にアーティスト名、保存の下にキャンセル。 |
| 横並び | 同じ曲の情報や、同列の選択肢に使う。日付はアーティスト名と同じ行に収まるときだけ右寄せ。幅が足りなければ日付の単位で折り返す。 |
| 左右の役割 | 左は画像・曲名・項目名、右は日付・件数・状態・遷移の矢印。文字は左揃え。独立した通知や全幅ボタンのラベルは中央揃え。 |
| 操作部品 | 送信・変更・確定はボタン、他サイトへの遷移はリンク、一覧や詳細への遷移は行全体を押せるようにする。入力中のキャンセルは操作終了として残し、ページの戻る操作にはブラウザ履歴を使う。 |

## リスナー画面の共通値

用語集の操作ガイドなどの詳細ページにも、リスナー画面と共通のヘッダーとフッターを表示する。ページ固有の戻るボタンは置かず、ブラウザの戻る操作を使う。

### ポコチャ用語集の操作ガイド

用語の説明と操作ガイドは、Pocochaでえむぴーの配信を見るリスナーに向けて書く。配信に固有の操作は、実際に探す名前や表示を使う。共通の仕組みを説明するときも、配信を見ながら役立つ場面を優先する。

- パチパチの操作ガイドを見本にする。操作する場所や条件が伝わりにくい用語に、一覧の説明から操作名でリンクする。同じ操作を指す用語はガイドを共用する。
- 表題は用語名を主見出しにし、その右に小さく操作名を置く。説明を先に書き、対応する画像をその後に置く。公式画像には出典を付け、画像に番号があるときは、参照する番号を手順本文に書く。
- 複数の手順に対応する画像がそろう場合は、各手順の直後に1枚ずつ置く。実機の画像は、操作に必要な箇所を切り出して使う。
- 操作ガイドの画像は、まず現行の公式ヘルプから各手順に対応する画面を探す。操作箇所が分かる公式画像がそろったら、事前確認なしで実装・公開する。足りない場合は、必要な画面と写してほしい箇所を具体的に伝え、えむぴーに実機のスクリーンショットを依頼する。
- 手順は、いつ・どこに何が出て何を押すかが分かる長さにする。前提が明らかな操作は省く。1つの操作は1文、複数の操作は番号付きで示す。
- 画像の出典が表示される場合、下の公式ヘルプは省く。画像が表示できない場合は公式ヘルプを出す。購入画面など操作に必要なリンクは別に置く。
- 日本語の用語名を共通で使い、操作名と手順は表示言語に合わせる。ブラウザで一覧へ戻ったときは、元のカテゴリ・検索語・スクロール位置を復元する。

| --- | --- |

| テキスト | 主文 `#1d1d1f`、補足 `#686870`、操作 `#0071e3`、警告 `#a82e25` |

| ページタイトル下 | リスナー側の左上のタイトル行の下端から、最初に見える本文・入力欄・一覧の上端まで16。共通値 `--page-title-gap` を使う。空の一覧やログイン案内にも適用し、先頭要素の上マージンを重ねない。 |

### 曲の画像と状態

- リスナー側で曲を一覧表示するときは、左に42px角の枠別ジャケット、右に曲名とアーティスト名を上下に置く。歌える曲の全曲・アーティスト別・検索結果、歌い終わった曲、お気に入り、リクエスト履歴、曲名の入力候補、「お気に入りから選ぶ」に適用する。閲覧用の一覧は共通の `historyRow`、入力用の候補は共通の `renderSongChoice` を使う。

- 山P枠は白いジャケット `yamapi-white.png`。「それ以外の歌まね」は赤い筆のバツ入り `other-smoke.png`。トップ・次回予約・ユーザーメニュー・曲詳細・履歴等で同じ枠の画像を使う。写真に置き換えず、角は大きい画像で5、コンパクトな画像で3を基準に丸める。
- 曲情報は「曲名 → アーティスト名」の順で共通表示。曲名16・ウェイト650、アーティスト名13・ウェイト400、上下の間隔3。リスナー側の曲一覧・入力候補・リクエスト概要では曲名を1行にし、収まらないときは末尾を「…」で省略する。曲ポップアップ・曲詳細では曲名の全文を折り返して表示する。長いアーティスト名は行内で折り返す。リクエストトップは未送信なら枠名、送信済みなら曲名とアーティスト名を表示する。
- 状態は曲の情報と同じ行の右側を基本とする。履歴の日付と状態は別の情報として扱う。「曲を変更」は曲詳細の下に置き、抽選前の変更可能な状態で表示する。
- タグは11、ウェイト600、上下3・左右7、丸型。最大12文字分の幅を目安に必要なら折り返す。選択行の矢印はタグの色に連動させない。曲の詳細ではタグを押すと共通ポップアップで状態の意味を表示する。記録済みの理由があるときは理由と今後の扱いも表示する。「持ち越し」は次の配信で抽選対象に戻ることを示す。

| チャレンジ | `#ffeadb` | `#93400e` |
| 未リクエスト・見送り | `#f0f0f3` | `#515158` |
| リクエスト済み・抽選待ち | `#e9f2ff` | `#174c83` |

| 当選・当選済み | `#e4f4eb` | `#206744` |
| 一時保留・持ち越し | `#fff0d5` | `#774613` |
| 取り下げ済み | `#fbe8e7` | `#8d3235` |

## リスナー画面ごとのルール

- **入口**。「はじめての方」「ログイン」は画面下部に縦並び。初回はパスコード設定、ログインは名前とパスコードを標準表示。名前だけの選択肢は下部リンク。同列のリンクが2件あるときだけ縦線で区切る。名前だけで始める場合の注意は赤。ログアウト結果は入口のボタンのすぐ上に短時間表示する。
- **トップ**。ヘッダー左のPと細字の「歌まねリクエスト β版」は一つのリンクで、どちらを押してもリクエストトップに戻る。本文は小さな挨拶の下に山P、それ以外の順で2行。枠ごとに1曲。募集回の番号はリスナーに表示しない。
- **現在の抽選枠・次の抽選枠への予約**。受付・順番待ち・予約は同じ曲詳細と入力パターンを使う。「次の抽選枠が開くまでお待ちください。」は中央、18・ウェイト600。予約できる場合だけ説明と「次の抽選枠への予約」をその下に置く。予約済みなら待機メッセージまで。
- **フォーム**。「アーティスト名」「曲名」などは入力枠内で空欄時15、入力済み・フォーカス時・プルダウンは左上の11。入力欄は全幅、高さ52、枠1px `#7d7d7f`、角10、背景 `#fdfdfd`。フォーカスは青。リクエスト・予約・曲変更・名前変更・バグ報告は、入力欄→補助操作または補足→主操作の順。入力欄・補助操作・補足の間隔は8、最後の表示要素から主操作まで16。入力文字16。山P枠のアーティスト名はプルダウン、それ以外は自由入力。曲候補は歌手と紐づけ、ひらがなの読みは入力補助として扱う。ハングル表記を登録した曲はリクエスト入力と「歌える曲」の検索で共用し、曲名は元の表記で表示する。
- **フォームの操作**。「リクエストする」「次の抽選枠に予約する」「変更する」など目的が分かる文言を使う。曲の編集は「曲を変更」。主操作は共通の form-actions を使い、全幅、高さ48以上、角10。無効時はグレーで表示する。キャンセルは直下に中央配置した下線付きの文字で、押せる高さは44以上。必須入力が揃うまで送信ボタンは無効。重複で送れなかったときの赤い説明は、その操作への応答として表示する。「歌える曲」にない曲は送信前に共通ポップアップで案内し、歌えない理由の記録がある場合は理由の案内を優先する。
- **三本メニュー**。上から「今の抽選枠で歌い終った曲」「歌える曲」「ポコチャ用語集」。その下を16px空けて「公式ホームページ」「トップ」の順に置く。「バグ報告/ご意見」はメニュー画面の下端に配置し、高さが足りない場合はスクロールで表示する。項目は高さ52以上、14・ウェイト600。項目間は余白で区別する。
- **ユーザーメニュー**。「リクエスト中の曲」を22で表示し、抽選待ちの自分の曲を最大2件。「リクエストを確認」はその下に全幅・高さ48以上・角10。その次に薄い「プロフィール」（14）を置き、項目に17角の線アイコンを添える。プロフィールの2番目に「お気に入り」を置き、保存したアーティストと曲を表示する。「ログアウト」は最下段で、実行前に確認する。
- **メニュー共通**。人物アイコンは三本線の左。閉じる×は両方で三本線と同じ位置。展開は400msで、項目は50msずつずらす。端末の動きを減らす設定を尊重する。
- **歌える曲の検索**。各階層の見出し行の下に、左に虫眼鏡を添えた丸い検索欄を置く。入力に合わせて直下の結果一覧を更新する。アーティスト一覧ではアーティスト名だけ、ほかの階層では曲名とアーティスト名で、開いている範囲から検索する。アーティストの行を押すと、その人の曲一覧を開く。
- **アーティストへのリンク**。歌える曲の「アーティスト」項目にはマイクのアイコンを使う。リスナー側で曲情報に添えるアーティスト名から、その人の「歌える曲」一覧を開ける。リクエスト入力中の候補は選択操作として扱う。
- **歌える曲の階層**。親ページは見出しの上に小さく表示し、タップで親の一覧へ戻れるようにする。現在のページ名は見出しサイズ。アーティスト一覧と曲一覧の上段は「歌える曲 › カテゴリ」。アーティスト個別は上段に「歌える曲 › カテゴリ › アーティスト」、下段にアーティスト名とそのすぐ右の星を置く。
- **曲数**。薄いグレーの14pxで表示する。「歌える曲」は各階層のタイトルのすぐ右、「今の抽選枠で歌い終った曲」は見出し行の右端に置く。
- **ポップアップ**。リスナー側はログアウト確認を基準に listener-dialog を共用する。白いカードは最大300px、角16px、背景を薄く暗くし、見出しは中央に17pxで置く。初期フォーカスは見出し。下の操作ボタンは高さ44px以上。曲一覧は曲名を上、アーティスト名を下に置き、薄い横線で区切る。
- **曲の操作**。曲一覧の曲名やジャケットから、曲情報とお気に入り操作を共通ポップアップで表示する。その曲のカテゴリが未リクエストなら入力済みのフォームへ進める。曲一覧のアーティスト名・星・状態タグの操作は個別に扱う。
- **お気に入り**。「歌える曲」と「今の抽選枠で歌い終った曲」の曲は行の右端に星を置く。アーティストの星は曲一覧を開いた先のタイトルのすぐ右に置く。保存済みの星は塗りつぶす。曲とアーティストを合わせたお気に入りが0件から1件になったとき、共通ポップアップで保存先を案内する。曲の詳細から初回登録した場合は、詳細を閉じてから案内を開き、案内を閉じると元の一覧に戻る。新規リクエストでは曲名欄の直下に小さな青文字と線の星で「お気に入りから選ぶ」を置き、同じ枠の保存曲を入力できる。その下に「歌える曲リストから選ぶ」を置く。お気に入りの曲は共通ポップアップで選び、リクエスト欄に入力する。「歌える曲リストから選ぶ」は同じ枠のアーティスト一覧を開く。アーティストを選ぶと、そのアーティストの曲一覧に進む。送信には通常のリクエスト操作を使う。
- **一覧の範囲**。「リクエスト履歴」は自分の記録。「今の抽選枠で歌い終った曲」は今の抽選枠分。「歌える曲」は歌唱記録から作り、山Pとそれ以外に分ける。履歴と歌唱済みは記録の日付を付ける。結果一覧とリクエスト画面は開いたときに取得し、送信・変更後はその操作の結果を取り直す。

## 管理画面と配信用ルーレット

- **管理の並び**。「今回当選中の曲」とその操作、その下に「ルーレット表示」。線で区切った下に「リクエスト一覧」。山Pとそれ以外、抽選前と処理後を分け、各表は初期状態で閉じる。管理本文は最大1060、左右24。幅600以下では左右16。
- **行の操作**。三点メニューから、その状態で意味のある操作だけを出す。抽選前は曲の変更や取り下げなど、処理後は抽選待ちへ戻す、歌えない理由の訂正など。個別の初期化はそのユーザーのその曲に作用する。右上の三本メニューから「ユーザー管理」「バグ報告」「入力候補」をそれぞれ独立した画面で開く。「リクエスト管理トップ」で戻れる。配信切り替えは確認してから実行する。ユーザー管理は名前とログイン方式を50件ずつ表示し、Pocochaの名前で絞り込める。
- **ルーレット**。管理の表から全画面で開く。「両方」「山P」「それ以外」の切り替えは幅312まで、各ボタンは高さ40以上。初期選択は山P。中央の青いP（直径60〜84）が回す操作。下の「設定」で回転時間を調整し、プレビューする。
- **結果**。回転中の盤面は曲名、停止後は中央の結果オーバーレイに曲名（30〜64）、下にアーティスト名（18〜28）。配信画面の結果に応募者名は載せない。「歌えない」「次の配信に持ち越す」は当選結果に対する操作。「歌えない」の理由は「知らない」「音源なし」。抽選結果を訂正したときは公開側の結果にも反映する。
- **更新と日付の境界**。管理は表示中に10秒ごとに取り直す。「次の配信を開始」の手動操作に加え、日本時間15時の切り替えがある。リスナーの歌唱一覧は抽選枠単位で、配信日が切り替わっても抽選枠が続く間は同じ一覧を使う。

## 実装を確認する場所

- リスナーの構造と文言は [index.html](index.html) と [listener.mjs](listener.mjs)。
- 色・曲の行・入力・状態タグは [style.css](style.css)。ヘッダーとフッターの共通寸法は [site-frame.css](site-frame.css)、リスナー固有の指定とメニューは [site-menu.css](site-menu.css)。
- 管理・抽選の構造と操作は [admin.html](admin.html) と [admin.mjs](admin.mjs)、配信用の寸法は [roulette-tabs.css](roulette-tabs.css)。
- 変更時は同じ役割の画面を横断して確認する。とくにスマホ幅、長いアーティスト名、未入力・入力中・入力済み、抽選前後、両方のメニュー、ブラウザの戻る操作を確認する。
