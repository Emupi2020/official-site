# 抽選・知らない曲の扱い（最新）

2026年11月22日更新。この文書の操作仕様を、初期版の「歌唱済み／見送り」ボタンの説明より優先する。

- 普段の操作は「回す／次を回す」。「次を回す」で、前の選択曲を歌唱済みにしてから次を抽選する。最後の1曲も同じ操作で消化できる。
- 「操作」メニューに「戻す」「知らない」を置く。歌唱済みボタンと見送りボタンは常時表示しない。
- 「知らない」は、歌手＋曲名に対してまだ覚えていない日時を記録する。当選した応募も、同じ曲の未消化応募も削除せず次回配信へ保留する。
- 当日に同じ曲が新しくリクエストされた場合も保留。受付回を変えても、その配信中は再抽選しない。
- 次回配信の開始操作で保留を抽選に戻す。知らない日時は残す。
- リスナーがその曲をリクエストする際には、送信前に日時付きで確認する。「リクエストする／曲を変更する」を選べる。古い確認のまま送られてきた場合はサーバーでも再確認を求める。
- 後日その曲を歌い、「次を回す」で歌唱済みになったら、知らない記録を消して案内を解除する。手動解除操作は不要。
- 再び「知らない」を押したら日時を更新する。別歌手の同名曲は別物として扱い、サジェストに関連付いた通称・ひらがな表記は同曲と判断する。
- 「戻す」は、直前の抽選・前曲消化・保留・知らない記録の変更を整合するよう取り消す。戻すまでに増えた新しいリクエストを消さない。
- 知らない記録は応募者の名前と関連付けず、歌手・曲・日時だけを保持する。入力候補と同様、30日の応募履歴削除とは別に扱う。

操作テスト版も同じルールを使う。既存の端末内テストデータは引き継ぎ、追加された項目がない古いデータにも対応する。

## ルーレット表示とリスナーの確認

- 公開ルーレットは画面の幅・高さに合わせて大きく表示する。見出し・ヘッダー・フッター・操作ボタンは置かず、停止後の曲名・歌手名だけを追加する。操作テスト版の画面切り替えタブは確認用として残す。
- リクエスト画面に「自分のリクエスト」「今回の歌唱済み」を折りたたみで追加する。
- 自分のリクエストは、送信した端末に保存したトークンで本人分だけを取得する。別の受付回のリクエストも一覧で確認できる。名前を入力しただけで他人の履歴を取得することはできない。
- 同曲の別の応募が歌われた場合、自分の応募が次回保留であることと、その曲自体は今回歌われたことを分けて表示する。
- 今回の歌唱済み一覧は曲名・歌手名・歌唱処理時刻だけを公開し、応募者名・トークンは含めない。選ばれただけ、知らない、保留の曲は歌唱済み一覧に入れない。
- 戻す操作で歌唱を取り消したら一覧にも反映する。受付回の変更では区切らず、次回配信の開始操作で今回の一覧を区切る。
- 新しい歌唱履歴は30日保持する。以前の保存データに時刻がない曲は、時刻を推測せず歌唱済みとして表示する。
