# 抽選・知らない曲の扱い（最新）

2026年11月22日更新。この文書の操作仕様を、初期版の「歌唱済み／見送り」ボタンの説明より優先する。

- 普段の操作は「回す／次を回す」。「次を回す」で、前の選択曲を歌唱済みにしてから次を抽選する。最後の1曲も同じ操作で消化できる。
- 「操作」メニューに「戻す」「歌えない」を置く。「歌えない」で「知らない」「音源なし」から理由を選ぶ。歌唱済みボタンと見送りボタンは常時表示しない。
- 「知らない」は、歌手＋曲名に対してまだ覚えていない日時を記録する。当選した応募も、同じ曲の未消化応募も削除せず次回配信へ保留する。
- 当日に同じ曲が新しくリクエストされた場合も保留。受付回を変えても、その配信中は再抽選しない。
- 次回配信の開始操作で保留を抽選に戻す。知らない日時は残す。
- リスナーがその曲をリクエストする際には、送信前に日時付きで確認する。「リクエストする／曲を変更する」を選べる。古い確認のまま送られてきた場合はサーバーでも再確認を求める。
- 後日その曲を歌い、「次を回す」で歌唱済みになったら、知らない記録を消して案内を解除する。手動解除操作は不要。
- 再び「知らない」を押したら日時を更新する。別歌手の同名曲は別物として扱い、サジェストに関連付いた通称・ひらがな表記は同曲と判断する。
- 「戻す」は、直前の抽選・前曲消化・保留・知らない記録の変更を整合するよう取り消す。戻すまでに増えた新しいリクエストを消さない。
- 知らない記録は応募者の名前と関連付けず、歌手・曲・日時だけを保持する。入力候補と同様、30日の応募履歴削除とは別に扱う。

操作テスト版も同じルールを使う。既存の端末内テストデータは引き継ぎ、追加された項目がない古いデータにも対応する。

## ルーレット表示とリスナーの確認

- 画面は管理側とリスナー側の2つ。独立した公開ルーレット画面は設けない。管理側の大きなルーレットを配信者が操作し、配信に映す。配信とWebの同時閲覧は前提にしない。
- ルーレットには曲名だけ、停止後は曲名・歌手名を表示する。応募者名は折りたたんだ管理欄内に置き、ルーレット部分には表示しない。
- リクエスト画面に「自分のリクエスト」「今回の歌唱済み」を折りたたみで追加する。
- 同じPococha名を入力すると、その名前で保存されている曲・予約・過去30日分の履歴を閲覧できる。未連携分は送信したブラウザーで修正する。パスコードまたはLINEで管理している分は、紐づいたアカウントでログインしているときだけ修正できる。
- パスコードは任意の半角数字4桁。登録時のPococha名とパスコードで、別のブラウザーから連携済みリクエストを取得できる。送信時のトークンがある同じ名前のリクエストは登録時とログイン時に引き継げる。名前だけで照会した曲は連携対象に含めない。
- 抽選を取り消して抽選待ちに戻った曲は、本人がもう一度修正できる。
- 一度パスコードを設定した名前で入るには、パスコードが必要。リクエストが残っている名前を初めて登録するときは、その名前で送信したブラウザーで設定する。
- 同曲の別の応募が歌われた場合、自分の応募が次回保留であることと、その曲自体は今回歌われたことを分けて表示する。
- 今回の歌唱済み一覧は曲名・歌手名・歌唱処理時刻だけを公開し、応募者名・トークンは含めない。選ばれただけ、知らない、保留の曲は歌唱済み一覧に入れない。
- 戻す操作で歌唱を取り消したら一覧にも反映する。受付回の変更では区切らず、次回配信の開始操作で今回の一覧を区切る。
- 新しい歌唱履歴は30日保持する。以前の保存データに時刻がない曲は、時刻を推測せず歌唱済みとして表示する。

## 歌えない理由

- 「知らない」「音源なし」は曲ごとに理由別の日時を記録する。別の理由を追加しても以前の理由を消さず、同じ理由は日時を更新する。
- リスナーが次回以降リクエストする際、記録された理由とそれぞれの日時を表示して確認を求める。確認後のリクエストは可能。
- 当選分・同曲の残りはどちらの理由でも次回へ残す。後日歌唱済みにしたときに理由をまとめて解除し、「戻す」で理由と日時も復元する。
- 既存の理由なしの知らない記録は「知らない」として引き継ぐ。

## 管理一覧と配信用ルーレット（2026-11-24）

- 管理画面の初期表示は曲・歌手・リクエスト者・状況・操作の表。ルーレットは初期表示しない。
- 表の下の「ルーレット」から、同じ管理画面内の全画面ダイアログを開く。ヘッダー、受付状況、管理一覧、応募者名は映さない。リスナー向けの別公開ページではない。
- 「回す／次を回す」で抽選し、停止後は曲名・歌手名のオーバーレイを表示。閉じる操作自体で歌唱済みにはしない。
- 結果オーバーレイを閉じるとルーレットに戻り、全画面を閉じると管理一覧に戻る。歌えない・戻すは管理側で行う。
- 回転中は管理画面への復帰を止め、二重抽選を防ぐ。

## 次の回への予約と常時受付（2026-11-24・最新）

- 手動の受付開始・終了、次の受付回ボタンは使わない。初期状態と旧保存データの受付終了フラグにかかわらず常時受付する。
- 今の回と次の回へそれぞれ1人1件ずつ。送信する回を明示し、古い回や2回先への送信はサーバーで拒否する。
- 次の回の予約は今の抽選に入れない。途中参加は今の回に追加できる。
- 抽選待ちと未処理の選択曲がなくなり、その回の全件を処理したら自動で次の回に進む。予約がなくても次の回で待ち、初期の空回だけで回数を増やさない。
- 歌えない曲・当日歌唱済みの重複曲は次回配信へ持越し、今の回の終了を妨げない。同曲の予約も同じ配信で重複歌唱しない。
- 回の切替と配信の切替は別。歌唱済み一覧や歌えない理由は回の切替で消さない。
- 切替を伴う操作を戻す際は回数も復元し、新しいリクエストと予約は消さずに残す。
- 名前訂正は今の回・次の回の待機／保留分に対して可能。同じ回の重複名と訂正前の名前の再利用を防ぐ。

## 山Pとそれ以外の2枠（2026-11-24・最新）

- リスナーは今回／次回の予約を選ぶ。第何回かという数値は画面や本人履歴に出さない。管理側では保持・表示する。
- 各回、同じ名前・同じ端末で山Pの歌まね1曲、それ以外の歌まね1曲まで。次回の予約も同じ2枠。枠の選択を偽っても歌手名でサーバーが検証する。
- 山下智久の別名、NEWS、修二と彰、亀と山Pを山P枠とする。既存データも歌手名から分類し、保存済みリクエストを消さない。
- サジェストは選択した枠と入力済み歌手名で絞る。
- 管理側は山Pのみ／それ以外のみ／両方から抽選対象を選ぶ。枠を変えるだけでは曲を消化しない。
- 一方の枠を処理し終えても、他方に未処理が残れば回を切り替えない。両枠を全て処理したら自動で次へ進む。予約は現在回の抽選に入れない。
- 管理側で歌手を修正して枠が変わる場合も、同じ回・同じ名前の枠の重複を拒否する。

## リスナー画面の縦ブロック（2026-11-24・最新）

- 共通のPococha名を入力し、山Pの歌まね／それ以外の歌まねを縦に並べる。切替タブは使わない。
- 最初は今回の入力欄だけを表示する。両方がリクエスト済みになったら、2つの枠の下に共通の「次回の予約」を表示する。開くと山Pとそれ以外の予約欄が並ぶ。
- 保存済みの予約は「自分のリクエスト」からも確認できる。
- フォームごとに送信対象の回・枠を保持する。受付回の数値はリスナーには表示しない。
- 名前訂正や歌えない理由の確認、歌手に紐づく候補、端末の本人履歴は維持する。
