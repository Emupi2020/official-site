# 歌まねリクエストの画面設計

最初の画面ではPococha名を入力して「はじめる」を押す。名前をブラウザーに保存し、次回は曲の入力画面から開く。LINEログインが有効になったときは、同じ入口から選べる。曲の入力画面では、名前を確認し、曲を選び、送信結果を確認できる順にする。

| 要素 | 使う理由と使う場所 |
| --- | --- |
| ブロック | 入力・修正できるまとまりをカードで示す。Pococha名、山Pの曲、それ以外の曲に同じ枠と余白を使い、確認表示に切り替わっても枠を保つ。両方をリクエストした後、2つのカードの下に共通の「次回の予約」を出す。開くと予約用の2枠が同じカード形式で並ぶ。履歴と注意事項はそれぞれ開閉行にする。 |
| 区切り線 | 入力行の範囲や、今回と次回、履歴の各項目の境目を示す。同じ曲の情報や、情報とそれを修正する操作は余白でまとめる。 |
| 色 | 青の塗りは送信、青の文字は修正などの補助操作を示す。開閉は矢印で示す。赤は直近の操作エラーに使う。状態や説明は通常の文字と補助色で示す。入力フォーカスには青い目印を出す。 |
| ボタン | 送信・予約・保存など確定する操作を押せる形にする。送信は塗りボタン、既存情報の修正と編集内の保存・キャンセルは文字ボタン。内容を読むための開閉は行全体を押せるようにする。 |
| 太字 | ページ名、枠の見出し、送信控えで最初に確認する曲名に使う。操作の中では送信と保存を強調する。歌手名、状態、補足は通常の太さにする。 |
| 縦の並び | 共通の名前から独立した二つの枠、履歴へと進む。曲名の下に歌手名と状態を置く。長い曲名も読めるよう曲名の横に操作を置かない。 |
| 横の並び | 項目名と入力値など、一組で読む短い情報に使う。確認時のPococha名と「名前を修正」は同じ行に置く。曲の状態と「曲を修正」も同じ行を使い、幅が足りないときは折り返す。 |
| 左右の配置 | 情報の読み始めを左にそろえる。右側は送信・修正など行や枠の末尾の操作、または項目に付随する件数と開閉矢印に使う。右側の文字も左から読む。 |
| 文言 | ラベルは項目名、状態は現在の結果、操作は動詞で書く。ページ先頭の名前は控えに繰り返さない。直前の送信に対するエラーと、後から見ても成立する「リクエスト済み」の状態を分ける。 |
